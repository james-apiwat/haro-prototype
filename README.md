# Haro (laptop prototype)

Haro เวอร์ชันแรกที่รันบนโน้ตบุ๊ก ใช้กล้องและลำโพงของคอม หน้า Haro วาดบนจอกลมขนาดเท่ากับจอ GC9A01 ที่จะใช้จริง (ขยาย 2 เท่า) เมื่อตัวหุ่นพร้อมแล้ว ต่อ ESP32 เข้าสาย USB ได้เลยโดยไม่ต้องแก้สมอง

ใช้ได้ 2 แบบ

| แบบ | เปิดด้วย | เหมาะกับ |
|---|---|---|
| Haro บนโน้ตบุ๊ก | `run_haro.bat` | ใช้กล้อง ไมค์ และลำโพงจริง ต่อ ESP32 ได้ (ดู "วิธีรัน") |
| Simulator 3 มิติ | `run_sim.bat` | ลองเลี้ยง Haro ในตัวหุ่นเสมือนก่อนมีของจริง และทดสอบการเรียนรู้แบบเร่งเวลา (ดู "Simulator") |

## Haro ทำอะไรได้

| พฤติกรรม | เกิดเมื่อ | Haro ทำอะไร |
|---|---|---|
| มองตามเรา | กล้องเห็นหน้า | ตาและหัวหันตามหน้าเรา |
| ทักทาย | เจ้าของหายไปเกิน 10 วินาทีแล้วกลับมา | ตายิ้ม แก้มแดง เด้งดีใจ ส่งเสียงทัก ยิ่งเจอบ่อยยิ่งดีใจมาก |
| เอียงคอสงสัย | ไมค์ได้ยินเสียงพูด | เอียงคอ ส่งเสียงสงสัย |
| ขี้อ้อนแต่มีฟอร์ม | เจ้าของอยู่แต่ไม่ลูบเกิน 30 วินาที | อ้อนด้วยท่าที่เจ้าของชอบที่สุด ถ้ายังเมินอีก 12 วินาทีจะงอน หันหนี แล้วแอบหันกลับมามอง |
| มีชีวิตของตัวเอง | ไม่มีใครอยู่ | มองไปรอบๆ กะพริบตา หายใจ ยิ่งว่างนานยิ่งช้าลง หาว แล้วหลับ |
| เข้าใจเจ้าของ | ทุกครั้งที่ทำท่าน่ารัก | ถ้าเจ้าของลูบหัวภายใน 5 วินาที ท่านั้นได้คะแนน แล้ว Haro จะทำท่านั้นบ่อยขึ้น และจำว่าเจ้าของมักอยู่ช่วงกี่โมง |

ท่าน่ารักมี 5 ท่า: `wiggle` ส่ายหัว, `tilt` เอียงคอ, `chirp` ร้องดีใจ, `bounce` เด้ง, `wink` ขยิบตา

## วิธีรัน

**Windows แบบง่ายที่สุด:** ดับเบิลคลิก `run_haro.bat` ครั้งแรกจะติดตั้งทุกอย่างให้ (ใช้เวลาสักพัก) ครั้งต่อไปจะเปิดทันที

**รันเอง (Windows, Mac, Linux)** ต้องมี Python 3.9 ขึ้นไป

```
python -m venv .venv
.venv\Scripts\activate          (Mac/Linux: source .venv/bin/activate)
pip install -r requirements.txt
python haro.py
```

ตัวเลือกเพิ่มเติม

```
python haro.py --camera 1       ใช้กล้องตัวที่ 2
python haro.py --no-mic         ปิดไมค์
python haro.py --no-camera      ใช้เมาส์แทนหน้า (ไม่มีกล้อง)
python haro.py --port COM3      ต่อกับ ESP32
python haro.py --mic-device 2   เลือกไมค์ (ดูเลขด้วย python pet_audio.py devices)
python haro.py --no-audio-pet   ปิดการลูบด้วยเสียง
```

## วิธีเล่น

| ทำอะไร | ผล |
|---|---|
| คลิกที่หน้า Haro หรือกด Space | ลูบหัว |
| ลูบตัวหุ่นจริงตรงไมค์ | ลูบหัว (ต้องเทรนโมเดลก่อน ดู "ลูบด้วยเสียง") |
| กด I | เปิดหรือปิดข้อมูล: state, คะแนนแต่ละท่า, ท่าที่ชอบที่สุด |
| กด M | สลับใช้เมาส์แทนหน้า (ทดสอบได้โดยไม่ต้องนั่งหน้ากล้อง) |
| กด Q หรือ Esc | ออก |

**ทดลองระบบเข้าใจเจ้าของ:** กด I ให้เห็นคะแนน แล้วลูบหัวทุกครั้งที่ Haro ส่ายหัว (wiggle) ไม่ลูบท่าอื่น สักพักคะแนน wiggle จะสูงสุด Haro จะส่ายหัวบ่อยขึ้น และใช้ท่านี้ตอนอ้อน

## ปรับค่า

ค่าทั้งหมดอยู่ส่วนบนของ `haro.py` เช่น `CLINGY_AFTER` (เมินกี่วินาทีถึงอ้อน), `NAP_AFTER` (อยู่คนเดียวกี่วินาทีถึงหลับ) ตอนนี้ตั้งไว้สั้นสำหรับเดโม

## ข้อมูลที่ Haro เก็บ

อยู่ในโฟลเดอร์ `data/` (สร้างเองตอนรันครั้งแรก)

- `haro_memory.json` ความจำของ Haro: จำนวนครั้งที่เจอ, จำนวนครั้งที่ถูกลูบ, คะแนนแต่ละท่า, นาทีที่เจ้าของอยู่แยกตามชั่วโมง
- `haro_log.csv` ทุกเหตุการณ์พร้อมเวลา เช่น owner_arrive, greet, trick, trick_liked, clingy, sulk ใช้วิเคราะห์ตอนทดสอบกับผู้ใช้
  - `petted` มีช่อง detail บอกว่าลูบมาจากไหน: `space`, `click`, `touch` หรือ `audio:<ชนิด>`
  - `pet_audio_start` และ `pet_audio_end` บอกชนิดการลูบและลูบนานกี่วินาที

ลบโฟลเดอร์ `data/` เมื่ออยากให้ Haro เริ่มนับใหม่ เช่น ก่อนให้ผู้ทดสอบคนใหม่เล่น (เสียงที่อัดไว้เทรนอยู่ใน `dataset/` จะไม่หายไปด้วย)

## Simulator: ลองเลี้ยง Haro ก่อนมีตัวหุ่นจริง

ตัวหุ่น 3 มิติบนเบราว์เซอร์ จำลองฮาร์ดแวร์ที่ทีมมีจริง ได้แก่ จอกลม GC9A01, กล้อง OV3660 บนหัว, เซอร์โว MG996R 360° หนึ่งตัวที่หมุนทั้งตัว และฟอยล์ 3 แผ่นที่ต่อกับ touch pin สมองแปลงมาจาก `haro.py` ทำงานเหมือนกันทุกอย่าง ไม่ต้องใช้กล้อง ไมค์ หรือ ESP32

### 1. เปิด

ต้องมี Python 3 (เวอร์ชันไหนก็ได้ ไม่ต้อง `pip install`) และเบราว์เซอร์ Chrome, Edge หรือ Firefox ไม่ต้องต่อเน็ต

- **Windows:** ดับเบิลคลิก `run_sim.bat` เบราว์เซอร์จะเปิด http://localhost:8765/sim/ ให้เอง ปล่อยหน้าต่างดำไว้ระหว่างเล่น ปิดหน้าต่างนั้นเมื่อเลิกใช้
- **Mac / Linux:** เปิด terminal ในโฟลเดอร์โปรเจกต์ (ที่มี `run_sim.bat`) รันคำสั่งข้างล่าง แล้วเปิด http://localhost:8765/sim/ กด Ctrl+C เมื่อเลิกใช้

```
python3 -m http.server 8765 --bind 127.0.0.1
```

ดับเบิลคลิก `sim/index.html` ตรงๆ จะใช้ไม่ได้ เพราะเบราว์เซอร์ไม่ยอมโหลดโค้ดจากไฟล์ในเครื่อง ต้องเปิดผ่านเซิร์ฟเวอร์ตามข้างบน

เมื่อหน้าเว็บขึ้นแล้ว กด **เริ่มเลย** (เบราว์เซอร์จะยอมให้เล่นเสียงหลังจากกดครั้งแรกนี้)

### 2. หน้าจอมีอะไรบ้าง

| ตำแหน่ง | สิ่งที่เห็น |
|---|---|
| กลางจอ | Haro บนโต๊ะ โน้ตบุ๊กด้านหลังแสดง log แบบเดียวกับที่ `haro.py` พิมพ์ |
| บนกลาง | Haro กำลังทำอะไร และจะเกิดอะไรต่อ เช่น "ท่าถัดไปในอีก 8 วิ" |
| ล่างซ้าย | **จอจริง 240×240** คือภาพที่ ESP32 ต้องวาด และ **ภาพจากกล้อง Haro** กรอบสีฟ้าคือหน้าที่หาเจอ ถ้าหาไม่เจอจะบอกเหตุผล (นอกภาพ ไกลเกินไป ใกล้เกินไป) |
| ขวา | สถานะเจ้าของ, เวลาที่เหลือก่อนอ้อนหรือหาว, คำสั่งที่ส่งให้ ESP32, คะแนนแต่ละท่า, เจ้าของจำลอง, ปุ่มบันทึกข้อมูล, เหตุการณ์ล่าสุด |
| ล่าง | ปุ่มลัด ใช้คีย์บอร์ดแทนได้ |

### 3. ปุ่มและการควบคุม

คุณคือเจ้าของที่นั่งหน้าโต๊ะ ตำแหน่งกล้องของคุณคือตำแหน่งหน้าของคุณ

| ทำอะไร | ผล |
|---|---|
| ลากเมาส์ตรงที่ว่าง | เดินรอบโต๊ะ Haro เห็นคุณเมื่ออยู่ในมุมกล้องของ Haro และห่าง 15 ถึง 150 ซม. |
| ล้อเมาส์ | เข้าใกล้หรือถอยออก |
| กดหรือลากบนหัว ข้างตัวซ้าย หรือข้างตัวขวา | ลูบ (ข้างในมีฟอยล์) กดค้างไว้ = ลูบค้าง ตรงจอ กล้อง และฐานไม่มีเซนเซอร์ |
| Space | ลูบ |
| T | พูดด้วย (เหมือนไมค์ได้ยินเสียง) |
| ปุ่ม "ใช้ไมค์" | ใช้ไมค์จริงแทนการกด T |
| L | ลุกออกจากโต๊ะ หรือกลับมานั่ง |
| X | ดูชิ้นส่วนข้างในพร้อมป้ายชื่อ |
| C | กลับมามุมเจ้าของ |
| O | เปิดตู้เสื้อผ้า เปลี่ยนชุดให้ Haro (Esc ปิด) |
| 1, 2, 3, 4 | เร่งเวลา 1×, 4×, 16×, 64× (เกิน 4× จะปิดเสียง) |
| M | เปิดหรือปิดเสียง (เลือกชุดเสียงได้ที่ท้ายแถบปุ่มด้านล่าง) |

### 4. ลองทำตามนี้

| อยากเห็น | ทำแบบนี้ |
|---|---|
| Haro หันตาม | ลากเมาส์ตรงที่ว่างช้าๆ ไปทางซ้ายหรือขวา Haro หมุนตัวจนหน้าคุณอยู่กลางภาพกล้อง ถ้าเดินไปด้านหลังเร็วๆ หรือถอยเกิน 150 ซม. Haro จะหาไม่เจอ |
| ทักทาย | กด L รอเกิน 10 วินาที แล้วกด L อีกครั้ง Haro ดีใจและส่งเสียงทัก ยิ่งเจอบ่อยยิ่งดีใจมาก |
| สอนท่าโปรด | รอให้ Haro ทำท่าที่อยากให้ทำบ่อย แล้วลูบหัวภายใน 5 วินาที จะมีข้อความ "Haro จำได้ว่าคุณชอบท่า..." ทำซ้ำหลายรอบ แถบของท่านั้นจะยาวขึ้น และเปลี่ยนเป็นสีชมพูเมื่อกลายเป็นท่าโปรด |
| อ้อนแล้วงอน | นั่งเฉยๆ ไม่ลูบ 30 วินาที Haro จะอ้อนด้วยท่าโปรด ถ้ายังไม่ลูบอีก 12 วินาที Haro จะงอน หันหนี แล้วแอบหันกลับมามอง |
| หาวแล้วหลับ | กด L แล้วกด 3 (เร่ง 16×) Haro หาวเมื่ออยู่คนเดียว 40 วินาที และหลับที่ 120 วินาที (240 วินาทีถ้าเป็นช่วงเวลาที่เจ้าของมักอยู่) กด T เพื่อปลุก |
| ลูบค้าง | กดเมาส์ค้างไว้บนหัว Haro ดีใจค้างและเอียงหัวพิงมือจนกว่าจะปล่อย |
| ชิ้นส่วนข้างใน | กด X เห็นตำแหน่งจอ กล้อง ESP32 ฟอยล์ เซอร์โว และสายไฟ ใช้ตอนวางแผนประกอบตัวจริง |
| เปลี่ยนชุด | กด O แล้วเลือกชุด |

### 5. เปลี่ยนชุดให้ Haro

กด **เปลี่ยนชุด** หรือ O จะเปิดตู้เสื้อผ้าเหนือแถบปุ่ม คลิกชุดเพื่อใส่ simulator จำชุดที่เลือกไว้ และ URL จะมี `?outfit=ชื่อชุด` ต่อท้าย ส่งลิงก์นี้ให้คนในทีม จะเปิดมาเจอชุดเดียวกัน

ชุดที่มีให้: คลาสสิก, ลูกเจี๊ยบ, แมวส้ม, ปาร์ตี้, มงกุฎทอง, ชุดกันหนาว, แตงโม

ใต้ชื่อชุดบอกว่า **ชุดบังกล้องกี่ % และบังจอกี่ %** ถ้าชุดบังกล้อง Haro จะหาหน้าไม่เจอจริงๆ และภาพจากกล้อง Haro จะขึ้นว่า "ชุดบังกล้อง" ใช้ตรวจแบบชุดก่อนทำของจริงให้ตัวหุ่น

**ทำชุดเองและแชร์ให้ทีม:** ชุดหนึ่งชุดคือโฟลเดอร์หนึ่งใน `sim/outfits/` มีไฟล์ `outfit.json` (สี ลาย ของแต่ง) รูป `.png` `.jpg` หรือ `.webp` และโมเดล 3 มิติ `.glb` ถ้ามี (ปั้นใน Blender ได้ โดยเปิดตัว Haro จาก `sim/outfits/_blender/haro-body.glb` แล้วปั้นรอบตัว) ทำเสร็จแล้วรัน `python sim/outfits/check_outfits.py` แล้ว commit กับ push คนอื่น `git pull` แล้วกด **โหลดรายการใหม่** ในตู้เสื้อผ้า ก็ได้ชุดเดียวกัน ถ้ายังไม่อยากใส่ใน repo ให้ลากโฟลเดอร์ชุดมาวางบนหน้า simulator เพื่อลองก่อน

วิธีเขียนไฟล์ชุด จุดยึดของแต่ง ขนาดของตัว Haro และแม่แบบสำหรับวาดลายเปลือก อยู่ใน [sim/outfits/README.md](sim/outfits/README.md)

### 6. ทดสอบการเรียนรู้ด้วยเจ้าของจำลอง

ใช้ดูว่า Haro เรียนรู้ความชอบได้จริงไหม โดยไม่ต้องนั่งลูบเอง เหมาะทำก่อน user study

1. กด **ล้างความจำ** สองครั้ง ถ้าอยากเริ่มจากศูนย์
2. ที่แผงขวาหัวข้อ "เจ้าของจำลอง" กด **เปิด** บอตจะนั่งหน้า Haro ส่วนคุณกลายเป็นผู้ชมที่ Haro มองไม่เห็น
3. ตั้งความน่าจะเป็นที่บอตจะลูบหลังแต่ละท่า และตอนอ้อน เช่น ส่ายหัว 70% ท่าอื่น 20%
4. กด 4 (เร่ง 64×) ประมาณ 30 วินาทีเท่ากับ 30 นาทีในการจำลอง
5. ดูบรรทัด "เลือกท่าที่บอตชอบที่สุด (20 ครั้งล่าสุด)" ถ้าเรียนรู้ได้ ตัวเลขควรสูงกว่า 20% (เท่ากับสุ่ม) มาก และแถบของท่านั้นเป็นสีชมพู ถ้าเลื่อนแถบความน่าจะเป็น ตัวนับนี้จะเริ่มนับใหม่
6. กด **บันทึก log.csv** แล้วนำไปวิเคราะห์ต่อ

ผลที่เคยลอง: ส่ายหัว 70% ท่าอื่น 20% เร่ง 64× ประมาณ 27 นาทีจำลอง Haro เลือกส่ายหัว 90% ของ 20 ครั้งล่าสุด ถ้าตั้งค่าใกล้กัน เช่น 40% กับ 30% จะต้องใช้เวลานานกว่านี้มาก (ดู `../research-notes.md` หัวข้อ 9.3)

### 7. ข้อมูลของ Simulator

- เก็บไว้ในเบราว์เซอร์ ปิดแล้วเปิดใหม่ความจำยังอยู่ แต่**ไม่ได้อยู่ในโฟลเดอร์ `data/`** และแยกตาม URL เช่น `localhost:8765` กับ `127.0.0.1:8765` เป็นคนละความจำ
- **บันทึก memory.json** และ **บันทึก log.csv** ดาวน์โหลดไฟล์รูปแบบเดียวกับ `data/haro_memory.json` และ `data/haro_log.csv` ของ `haro.py`
- **โหลด memory.json** เอาความจำจาก `haro.py` มาเล่นต่อใน simulator ได้
- **ล้างความจำ** กดสองครั้งเพื่อยืนยัน
- เหตุการณ์ที่มีเฉพาะใน simulator
  - `petted` ช่อง detail บอกที่มาของการลูบ: `touch:crown` (หัว), `touch:left` (ข้างซ้ายของ Haro), `touch:right`, `space`, `button` หรือ `bot` (เจ้าของจำลอง)
  - `pet_touch_start` จุดที่แตะ และ `pet_touch_end` จุดที่แตะ ชนิด (`pat` แตะสั้น, `stroke` ลูบ, `hold` แตะค้าง) และนานกี่วินาที
  - `outfit` ช่อง detail คือชื่อโฟลเดอร์ของชุดที่เปลี่ยนไปใส่ (ชุดที่ลองจากเครื่องขึ้นต้นด้วย `local:`)

### 8. สิ่งที่ simulator ทำต่างจาก `haro.py`

เพราะจำลองฮาร์ดแวร์ที่มีจริง

- MG996R 360° สั่งได้แค่ความเร็ว ถ้าเห็นหน้า Haro หมุนตัวจนหน้าอยู่กลางภาพ ถ้าไม่เห็นหน้า จะหมุนไปทางที่สมองอยากมอง โดยนับจากทิศที่เห็นเจ้าของครั้งล่าสุด ตอนทำท่า wiggle และตอนถูกลูบจะส่ายตัว และหยุดที่ ±160° กันสายพัน
- เอียงคอ (roll) ใช้หมุนภาพบนจอแทน
- ตัวจริงไม่มีตัววัดมุม ต้องประมาณมุมจากเวลาที่สั่งหมุน แต่ simulator รู้มุมจริง
- แผงขวาแสดงทั้งคำสั่ง `H` และ `E` ที่ `haro.py` ส่งตอนนี้ และความกว้างพัลส์ (µs) ที่เซอร์โวต้องได้จริง (1500 = หยุด)

## ลูบด้วยเสียง (เตรียมไว้ใช้กับตัวหุ่นจริง)

Haro ฟังเสียงลูบจากไมค์ แล้วดีใจเหมือนตอนคลิก ลูบค้างไว้ Haro จะดีใจค้างและเอียงหัวพิงมือจนกว่าจะหยุดลูบ ทำงานเมื่อมีไฟล์ `models/petting_audio.joblib` แล้วเท่านั้น ถ้ายังไม่มี Haro ทำงานเหมือนเดิม

**ไมค์ต้องอยู่ติดตัวหุ่น** ไมค์ของโน้ตบุ๊กอยู่ไกล ได้ยินเสียงลูบเบามาก ให้ใช้ไมค์หูฟัง (แบบมีสายที่เสียบคอมได้) แปะเทปไว้ด้านในกล่องหรือตัวหุ่น แล้วลูบด้านนอกตรงนั้น ไมค์จะได้ยินชัดเหมือน contact mic ถ้ายังไม่มีตัวหุ่น ใช้กล่องกระดาษแทนก่อนได้ **ใช้ไมค์และตำแหน่งเดียวกันทั้งตอนอัด ตอนเทรน และตอนใช้จริง** ถ้าเปลี่ยนไมค์หรือย้ายไมค์ต้องอัดและเทรนใหม่

ต้องติดตั้ง scikit-learn เพิ่ม ถ้าเคยรัน `run_haro.bat` มาก่อน ให้ลบไฟล์ `.venv\haro_ready.txt` แล้วรันใหม่หนึ่งครั้ง

**1. หาเลขไมค์**

```
python pet_audio.py devices
```

ถ้าไม่ใช่ตัวที่มีเครื่องหมาย `>` ให้เติม `--device <เลข>` ในทุกคำสั่งข้างล่าง และ `--mic-device <เลข>` ตอนรัน haro.py

**2. อัดเสียง** ครั้งละ 30 วินาที แต่ละไฟล์จะไปอยู่ใน `dataset/petting/<ประเภท>/`

```
python pet_audio.py record --label stroke     ลูบต่อเนื่องตลอด 30 วินาที
python pet_audio.py record --label normal     ทุกอย่างที่ไม่ใช่การลูบ
```

- อย่างน้อย **5 ไฟล์ต่อประเภท** อัดต่างวัน ต่างคน ต่างแรงลูบ ยิ่งหลากหลายยิ่งใช้งานจริงได้ดี
- `normal` ต้องมีเสียงที่ Haro จะเจอจริง: เงียบ คุยกัน พิมพ์คีย์บอร์ด จับหรือยกตัวหุ่นโดยไม่ลูบ เปิดเพลง เสียงพัดลมหรือแอร์
- อยากให้ Haro แยกแบบการลูบได้ ให้เพิ่มประเภทเอง เช่น `--label scratch` (เกา) หรือ `--label pat` (ตบเบาๆ) ชื่อโฟลเดอร์คือชื่อประเภท ทุกประเภทที่ไม่ใช่ `normal` นับเป็นการลูบ

**3. เทรน**

```
python pet_audio.py train
```

ลองโมเดล 3 แบบ (logistic regression, random forest, MLP) ทดสอบแบบแยกไฟล์ แล้วเลือกตัวที่ดีที่สุด รายงานอยู่ที่ `models/petting_audio_report.txt` ใช้ใส่ในรายงานวิชาได้

- **ลูบหลอก** คือเสียงอื่นที่ถูกทายว่าเป็นการลูบ ตัวนี้สำคัญที่สุด เพราะทำให้ Haro ให้คะแนนท่าผิด
- **พลาดลูบ** คือลูบจริงแต่ Haro ไม่รู้
- ตัวเลขดีเกินจริงถ้าทุกไฟล์อัดในสภาพเดียวกัน ให้อัดหลายสภาพ

**4. ลองลูบดูผลสด**

```
python pet_audio.py live
```

เห็นแถบความน่าจะเป็นว่ากำลังลูบ และข้อความตอนเริ่มลูบหรือหยุดลูบ ถ้าลูบหลอกบ่อยให้เพิ่ม `PET_ENTER` ใน `haro.py` (ลองใน live ด้วย `--enter 0.85`) ถ้าลูบแล้วไม่ค่อยติดให้ลดลง หรืออัดเสียงลูบเพิ่มแล้วเทรนใหม่

**5. รัน Haro** ตามปกติ กด I จะเห็นบรรทัด `pet-audio` บอกความน่าจะเป็นและชนิดการลูบ คลิกและ Space ยังใช้ลูบได้เหมือนเดิม

ข้อควรรู้

- ระหว่างที่ Haro ส่งเสียงเองและอีกประมาณ 1 วินาทีหลังจากนั้น Haro จะไม่ฟังการลูบ กันไม่ให้ได้ยินเสียงตัวเองแล้วคิดว่าถูกลูบ
- เสียงลูบไม่นับเป็นเสียงพูด Haro จะไม่เอียงคอสงสัยตอนถูกลูบ
- ถ้าแก้ `features()` ใน `pet_audio.py` ต้องเพิ่ม `FEATURE_VERSION` แล้วเทรนใหม่ โมเดลเก่าจะไม่ถูกโหลด

## ต่อกับตัวหุ่นจริง (สำหรับคนทำ ESP32)

รัน `python haro.py --port COM3` (เปลี่ยนเป็นพอร์ตของบอร์ด) สื่อสารผ่าน USB serial ที่ 115200 baud ทีละบรรทัด

| ทิศทาง | คำสั่ง | ความหมาย |
|---|---|---|
| คอม → ESP32 | `H <pan> <roll>` | มุมหัวเป็นองศา `pan` หันซ้ายขวา -35 ถึง 35 (บวก = หันไปทางขวาของคนที่นั่งมอง), `roll` เอียงคอ ประมาณ -20 ถึง 20 |
| คอม → ESP32 | `E <expr>` | หน้าตา: `normal`, `happy`, `sleepy`, `sleep`, `sad`, `surprised`, `wink` |
| ESP32 → คอม | `T` | มีคนแตะ touch sensor (นับเป็นการลูบหัว) |

คอมส่ง `H` ไม่เกิน 20 ครั้งต่อวินาที และส่งเฉพาะตอนค่าเปลี่ยน เสียงยังเล่นจากลำโพงคอม การวาดตาบนจอ GC9A01 ให้ดูหน้าตาแต่ละแบบจากหน้าต่างของ `haro.py` แล้วย่อลงครึ่งหนึ่ง
